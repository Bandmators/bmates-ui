# 접근성

BMates UI는 접근 가능한 인터페이스를 만들기 위한 구성 요소를 제공합니다.
하지만 주변 콘텐츠와 레이블, 포커스 흐름, 사용자 피드백은 애플리케이션에서
설계해야 합니다. 이 가이드에서는 라이브러리 전반에 적용되는 원칙을 설명합니다.

키보드 조작, 포커스 동작, ARIA 속성이 특정 컴포넌트에 따라 달라지는 경우에는
해당 컴포넌트 문서에서 설명합니다.

## 시맨틱 요소에서 시작하기

모양만이 아니라 의미와 동작을 기준으로 컴포넌트를 선택합니다. 버튼, 링크,
입력 요소, 제목, 표와 같은 네이티브 요소를 일반 `div`나 `span`으로 다시
구현하지 않습니다.

BMates UI 컴포넌트 주변에 애플리케이션 마크업을 추가할 때는 다음을 확인합니다.

- 제목의 단계가 논리적인 순서를 유지하는지 확인합니다.
- 페이지 이동에는 링크를, 동작 실행에는 버튼을 사용합니다.
- 표의 헤더와 데이터 셀 관계를 유지합니다.
- 임의의 포커스 순서를 만드는 양수 `tabIndex`를 피합니다.

## 접근 가능한 이름 제공하기

인터랙티브 요소에는 목적을 설명하는 이름이 필요합니다. 가능한 경우 모든
사용자가 볼 수 있는 텍스트를 사용합니다. 아이콘만 있는 버튼처럼 시각적
레이블을 제공하기 어려운 경우에는 `aria-label`을 사용합니다.

폼 레이블과 컨트롤은 일치하는 `htmlFor`와 `id`로 연결합니다.

```tsx
<Label htmlFor="profile-name">프로필 이름</Label>
<Input id="profile-name" name="profileName" />
```

필드 작성에 필요한 도움말이나 오류 메시지는 `aria-describedby`로 연결합니다.

```tsx
<Input
  id="email"
  aria-describedby="email-help email-error"
  aria-invalid={hasError}
/>
<p id="email-help">계정에 연결된 이메일을 입력하세요.</p>
{hasError && <p id="email-error">올바른 이메일을 입력하세요.</p>}
```

## 키보드 접근 유지하기

포인터로 실행할 수 있는 모든 동작은 키보드로도 사용할 수 있어야 합니다.
네이티브 인터랙티브 요소에는 이미 적절한 키보드 동작이 있으므로 특별한 이유
없이 요소를 교체하거나 키 이벤트를 가로채지 않습니다.

- 모든 동작 가능한 컨트롤에 `Tab`으로 접근할 수 있어야 합니다.
- 네이티브 동작을 중복 실행하거나 차단하는 키 핸들러를 추가하지 않습니다.
- 입력이나 브라우저 단축키와 충돌하는 애플리케이션 단축키를 피합니다.
- `Tab`과 `Shift+Tab`으로 정방향과 역방향 포커스 순서를 확인합니다.

## 포커스를 명확하고 예측 가능하게 만들기

동일하게 명확한 표시로 대체하지 않는 한 포커스 아웃라인을 제거하지 않습니다.
BMates UI와 일관된 사용자 정의 포커스 UI에는 `--focus-border`와
`--focus-shadow`를 사용할 수 있습니다.

사용자의 맥락이 바뀌고 다음 대상이 명확한 경우에만 프로그래밍 방식으로 포커스를
이동합니다. 오버레이 열기와 닫기처럼 컴포넌트가 관리하는 동작은 해당 컴포넌트
문서의 안내를 따릅니다.

## 상태를 명확하게 전달하기

선택, 유효성 검사, 로딩, 실패 상태를 색상만으로 전달하지 않습니다. 색상과 함께
텍스트, 아이콘 또는 다른 인지 가능한 표시를 제공합니다.

네이티브 상태 속성이 있다면 이를 우선 사용하고, 네이티브 HTML만으로 표현할 수
없는 동작에만 ARIA 상태를 추가합니다. 비활성화된 컨트롤은 시각적으로 구별되어야
하며 모든 입력 방식에서 사용할 수 없어야 합니다.

애플리케이션이 관리하는 비동기 작업 결과는 화면에만 표시하지 말고 지속되는 상태
메시지나 적절한 live region을 통해 전달합니다.

## 대비와 모션 환경설정 존중하기

라이트 및 다크 테마에서 콘텐츠를 읽을 수 있도록 semantic color token을
사용합니다. 테마 값을 재정의한 뒤에는 muted text, border, focus indicator,
상태 색상 위의 텍스트 대비를 확인합니다.

애플리케이션에서 추가하는 애니메이션은 `prefers-reduced-motion`을 존중해야
합니다. 모션을 줄이거나 비활성화해도 중요한 정보와 동작을 사용할 수 있어야
합니다.

```css
@media (prefers-reduced-motion: reduce) {
  .app-transition {
    animation: none;
    transition: none;
  }
}
```

## 검토 목록

인터페이스를 배포하기 전에 다음을 확인합니다.

- 키보드만 사용해 전체 흐름을 탐색합니다.
- 모든 컨트롤에 접근 가능한 이름이 있는지 확인합니다.
- 레이블, 도움말, 오류 메시지가 코드상으로 연결되어 있는지 확인합니다.
- 포커스가 항상 보이고 논리적인 순서로 이동하는지 확인합니다.
- 색상 없이도 상태와 유효성 검사 결과를 이해할 수 있는지 확인합니다.
- 텍스트 크기와 브라우저 배율을 높여 라이트 및 다크 테마를 검토합니다.
- 모션 감소 환경설정을 활성화해 테스트합니다.
