# 디자인 규약

[디자인 토큰](/ko/guide/tokens)이 _어떤 값이 존재하는지_ 를 정의한다면, 이
문서는 _컴포넌트가 그 값을 어떻게 써야 하는지_ 를 정의합니다. 목적은 임의의 두
컴포넌트를 나란히 놓았을 때 의도된 조합처럼 보이게 하는 것입니다.

아래 규칙은 모두 강제 사항입니다. 규칙을 어긴 컴포넌트는 변형이 아니라 버그로
취급합니다. 감사(audit)와 리뷰에서 인용할 수 있도록 번호를 붙였습니다
(`DR-3.2`).

## 1. 그리드

모든 길이 값은 기본 루트 16px 기준으로 정수 픽셀에 떨어져야 합니다.
`1rem = 16px`이므로, 이는 모든 값이 `0.0625rem`(1px)의 정수배 — 실무적으로는
`0.125rem`(2px)의 정수배 — 여야 한다는 뜻입니다.

시스템은 두 단계의 granularity를 씁니다.

| 단계          | 스텝             | 적용 범위                                       |
| ------------- | ---------------- | ----------------------------------------------- |
| **레이아웃**  | `0.25rem` (4px)  | margin, 컨테이너 패딩, 치수                      |
| **컴포넌트**  | `0.125rem` (2px) | 컨트롤 내부 패딩, 컴포넌트 자체 파트 간 gap, 헤어라인 인셋, 중첩 radius 보정 |

이는 업계 표준과 일치합니다. Tailwind의 스케일은 4px 기반이지만 `1.5`(6px),
`2.5`(10px), `3.5`(14px)를 포함하고, Carbon의 spacing 스케일은
`$spacing-01` = `0.125rem`에서 시작하며, Polaris와 Atlassian도 2px 하프 스텝을
제공합니다.

**DR-1.1 — 레이아웃 간격은 4px의 배수입니다.**
컴포넌트 사이의 위치를 결정하는 값 — margin, 컨테이너 패딩, width, height — 은
`BMateSpacing` 스케일에서 가져옵니다.

| 토큰  | 값      | px  |
| ----- | ------- | --- |
| `1`   | 0.25rem | 4   |
| `2`   | 0.5rem  | 8   |
| `3`   | 0.75rem | 12  |
| `4`   | 1rem    | 16  |
| `5`   | 1.25rem | 20  |
| `6`   | 1.5rem  | 24  |
| `8`   | 2rem    | 32  |
| `10`  | 2.5rem  | 40  |
| `12`  | 3rem    | 48  |
| `16`  | 4rem    | 64  |
| `20`  | 5rem    | 80  |
| `24`  | 6rem    | 96  |

**DR-1.2 — 컴포넌트 내부 간격은 2px 하프 스텝을 쓸 수 있습니다.**
컨트롤 내부 패딩, 헤어라인 인셋, 중첩 radius 보정에는 `0.125rem` 단위를 허용합니다.
`0.375rem`(6px), `0.625rem`(10px), `0.875rem`(14px)은 모두 정당한 값입니다.
컨트롤의 밀도를 조절하는 지점이라 4px 스텝으로는 목표 높이를 깔끔하게 맞추기
어렵기 때문입니다.

하프 스텝은 컴포넌트가 소유한 내부 파트 간의 `gap` — 메뉴 리스트의 행, 탭 트랙의
트리거 — 에도 적용됩니다. 다만 `margin`과, 사용하는 쪽이 서로 다른 두 컴포넌트
사이에 주는 gap에는 적용되지 않습니다. 6px 떨어진 두 컨트롤은 실수처럼 보이고,
8px 떨어지면 의도처럼 보입니다.

**DR-1.3 — 모든 길이는 정수 픽셀로 떨어져야 합니다.**
판정 기준은 `값 ÷ 0.0625`가 정수인지입니다. `0.15rem`(2.4px), `0.55rem`(8.8px),
`0.6rem`(9.6px), `0.45rem`(7.2px), `0.1rem`(1.6px), `0.3rem`(4.8px)은 이를
통과하지 못하므로 금지합니다.

서브픽셀 길이는 단순히 "조금 어긋난" 정도가 아닙니다. 브라우저는 엘리먼트의
절대 위치를 기준으로 반올림하기 때문에, 같은 컴포넌트가 페이지의 어디에
놓이느냐에 따라 테두리 두께가 다르게 렌더링됩니다. `8.8px` 패딩 위의 1px
테두리는 스크롤하거나 부모가 움직일 때마다 두꺼워졌다 얇아졌다 합니다.

**DR-1.4 — 상대 단위와 뷰포트 단위는 간격이 아닙니다.**
`%`, `em`, `vh`, `vw`는 레이아웃 제약(`width: 100%`, `max-height: 100vh`)에는
쓸 수 있지만 padding, margin, gap, font-size에는 쓰지 않습니다. 컴포넌트가
통제할 수 없는 문맥에 의존하게 되기 때문입니다.

## 2. 컨트롤 높이

**DR-2.1 — 모든 인터랙티브 컨트롤은 하나의 높이 스케일을 공유합니다.**
같은 줄에 놓일 수 있는 클릭·입력 요소 — `Button`, `Input`, `Select` 트리거,
`Search` 입력, `Toggle`, `Tabs` 트리거, `Pagination` 링크, `Textarea`(최소 높이) —
는 다음 값을 따릅니다.

| 사이즈 | 높이            | 폰트 크기 | 좌우 패딩 |
| ------ | --------------- | --------- | --------- |
| `sm`   | 32px (`2rem`)   | `sm` 14px | 12px      |
| `md`   | 40px (`2.5rem`) | `sm` 14px | 16px      |
| `lg`   | 48px (`3rem`)   | `md` 16px | 24px      |

**높이는 계산 결과가 아니라 선언 값입니다.** 세로 패딩은 폰트 메트릭에 따라
달라지므로, 컨트롤은 높이를 명시적으로 선언하고 flexbox로 콘텐츠를 정렬해야
합니다. `padding-y + line-height + border`의 합이 높이를 결정하게 두지 마세요.

```css
/* ✓ 높이가 계약이다 */
.bm-button {
  display: inline-flex;
  align-items: center;
  min-height: var(--bm-control-h);
}
.bm-button--size-md {
  --bm-control-h: 2.5rem;
  padding-inline: 1rem;
}
```

이런 컨트롤의 세로 패딩은 `DR-1.1`의 예외입니다. 패딩이 아니라 높이가 관리되는
치수이기 때문입니다. 가로 패딩은 예외가 아닙니다.

**DR-2.2 — 높이는 size prop이 정하며, 콘텐츠가 정하지 않습니다.**
아이콘이 있는 `Button`과 텍스트만 있는 `Button`은 같은 사이즈에서 높이가
동일해야 합니다.

**DR-2.3 — 아이콘 전용 컨트롤은 정사각형입니다.**
`size-icon`은 `md`와 같은 높이를 쓰고 좌우 패딩을 동일하게 둡니다.

## 3. 패딩

**DR-3.1 — 가로 패딩은 세로 패딩의 약 2배입니다.**
컨트롤들이 한 가족처럼 읽히게 만드는 밀도 비율입니다.
버튼 기준 `sm: 6/12`, `md: 8/16`, `lg: 12/24`.

**DR-3.2 — 컨테이너 패딩은 컨테이너의 위계에 비례합니다.**

| 표면                                                      | 패딩        |
| --------------------------------------------------------- | ----------- |
| 메뉴 아이템 (`Dropdown`, `Select`, `Search`, `ContextMenu`) | `8px 12px`  |
| Alert / 인라인 알림                                        | `12px 16px` |
| `Card`                                                     | `20px`      |
| `Dialog` / `Toast`                                         | `24px` / `16px` |

**DR-3.3 — 같은 중첩 단계의 형제 컴포넌트는 같은 패딩을 씁니다.**
`Dropdown`, `Select`, `Search`, `ContextMenu`의 아이템은 동일한 프리미티브이므로
픽셀 단위로 같아야 합니다. 값이 갈라지면 버그입니다.

## 4. 바깥 여백

**DR-4.1 — 컴포넌트는 자신의 바깥 margin을 갖지 않습니다.**
공개 컴포넌트의 루트 엘리먼트에는 `margin`이 없습니다. 형제 간 간격은 부모가
`gap`으로 책임집니다.

이유: margin이 내장된 컴포넌트는 조합할 수 없습니다. 사용하는 쪽에서 CSS를
덮어쓰지 않고는 그 여백을 제거할 방법이 없습니다.

```css
/* ✗ */ .bm-accordion__item { margin-bottom: 0.5rem; }
/* ✓ */ .bm-accordion       { display: flex; flex-direction: column; gap: 0.5rem; }
```

**DR-4.2 — 내부 margin은 타이포그래피 리셋 용도로만 허용합니다.**
제목·문단의 `margin: 0`, 리치 텍스트 슬롯의
`:first-child { margin-top: 0 }` / `:last-child { margin-bottom: 0 }`.

**DR-4.3 — 인접 요소 간격은 margin이 아니라 `gap`으로 만듭니다.**
컨트롤 내부의 아이콘–레이블 간격도 포함합니다.

## 5. 타이포그래피

**DR-5.1 — 폰트 크기는 스케일에서 가져옵니다.**
`xs 12` · `sm 14` · `md 16` · `lg 18` · `xl 20` · `2xl 24` · `3xl 30` · `4xl 36`.
`0.85rem`, `0.74rem`, `0.72rem`, `font-size: 75%` 같은 값은 스케일 밖이므로
금지합니다.

**DR-5.2 — line-height는 3단계 스케일에서 가져옵니다.**

| 토큰      | 값  | 용도                             |
| --------- | --- | -------------------------------- |
| `tight`   | 1.2 | 제목, 한 줄짜리 컨트롤 레이블    |
| `normal`  | 1.5 | 본문, 설명, 여러 줄 콘텐츠       |
| `relaxed` | 1.7 | 긴 산문 블록                     |

**DR-5.3 — `line-height: 1`은 금지합니다.**
디센더(`g`, `y`, `p`)가 잘리고, 세로 정렬이 폰트에 의존하게 됩니다. `tight`를
쓰세요.

**DR-5.4 — 고정 높이 컨트롤 안의 텍스트는 `tight`를 씁니다.**
높이는 `DR-2.1`이 정하므로 라인 박스가 높이를 좌우해서는 안 됩니다.

**DR-5.5 — 굵기는 의미를 갖습니다.**
`400` 본문 · `500` 인터랙티브 레이블 · `600` 섹션 제목 · `700` 알림 내 강조.
그 외 값은 쓰지 않습니다.

## 6. Radius

**DR-6.1 — radius는 컴포넌트 종류가 아니라 표면의 크기에 대응합니다.**

| 토큰            | 값     | 적용 대상                                        |
| --------------- | ------ | ------------------------------------------------ |
| `--radius-sm`   | 8px    | 메뉴 아이템, 배지, 탭, 페이지네이션, 툴팁        |
| `--radius`      | 10px   | 컨트롤: 버튼, 인풋, 텍스트영역, 토글, 알림       |
| `--radius-lg`   | 14px   | 떠 있는 표면: 카드, 다이얼로그, 토스트, 아코디언 |
| `--radius-full` | 9999px | 알약형, 아바타, 스위치 트랙                      |

**DR-6.2 — 중첩 radius는 `바깥값 - 패딩`입니다.**
둥근 부모 안의 둥근 자식은 `calc(var(--radius) - <부모 패딩>)`을 쓰며, 부모와
같은 값을 쓰지 않습니다.

**DR-6.3 — radius 리터럴을 직접 쓰지 않습니다.**
`border-radius: 4px`, `border-radius: 50%`는 각각 `--radius-sm`, `--radius-full`
토큰으로 대체합니다.

## 7. 테두리와 고도

**DR-7.1 — 테두리 두께는 `1px`입니다.**
의도적인 강조 엣지(`Alert`의 `border-left-width`)만 예외로 `0.25rem`을 씁니다.

**DR-7.2 — 그림자와 강한 테두리는 배타적입니다.**
하나의 표면은 `--shadow-*` 또는 `--border-strong` 중 하나만 최대 강도로 씁니다.
카드는 `--border` + `--shadow-sm`, 다이얼로그는 테두리 없이 `--shadow-lg`.

**DR-7.3 — 포커스는 모든 곳에서 동일합니다.**
포커스 가능한 요소는 `:focus-visible`에서 `--focus-border` + `--focus-shadow`를
쓰며, 대체 표시 없이 인디케이터를 제거하지 않습니다.

## 8. 모션

**DR-8.1 — 트랜지션은 `var(--transition)`을 씁니다.**
`150ms`, `.2s`, `200ms`, `.25s` 같은 리터럴은 금지합니다. 오버레이의 등장·퇴장
애니메이션만 `0.15s`로 예외를 둡니다.

**DR-8.2 — `all`이 아니라 개별 속성을 트랜지션합니다.**
`transition: all`은 레이아웃 속성까지 애니메이션해 버벅임을 만듭니다.

## 9. 조합

**DR-9.1 — 같은 사이즈의 컨트롤은 한 줄에서 네 변이 모두 맞습니다.**
`Button size="md"`, `Input`, `Select`를 나란히 놓으면 끊김 없는 40px 띠가
만들어져야 합니다.

**DR-9.2 — 컨트롤 안의 아이콘은 16px(`sm`/`md`) 또는 20px(`lg`)입니다.**
`rem`으로 선언하고 `align-items: center`로 정렬합니다.

**DR-9.3 — 조합된 컨트롤 사이의 기본 간격은 8px입니다.**
그룹으로 묶인 섹션은 12px, 서로 무관한 블록은 16px.

## 감사 체크리스트

컴포넌트를 추가하거나 수정할 때 확인합니다.

- [ ] 모든 길이 값이 4px 그리드 위에 있는가 (DR-1.1)
- [ ] 높이가 공유 컨트롤 스케일과 일치하는가 (DR-2.1)
- [ ] 루트 엘리먼트에 margin이 없는가 (DR-4.1)
- [ ] 폰트 크기와 line-height가 토큰에서 왔는가 (DR-5.1, DR-5.2)
- [ ] radius가 토큰이며 표면 위계와 맞는가 (DR-6.1, DR-6.3)
- [ ] 포커스 상태가 공유 포커스 토큰을 쓰는가 (DR-7.3)
- [ ] 트랜지션이 `var(--transition)`을 쓰고 속성을 명시하는가 (DR-8)
